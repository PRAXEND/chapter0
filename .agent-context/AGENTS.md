# Agent 团队开发规范 · 1.0.0

共享事实以仓库为准；个人记忆不能替代项目资料。

## 接手

- 检查仓库、分支、提交和已有未提交改动，保留他人的工作。
- 读 [PROJECT](docs/PROJECT.md)、当前 [任务](docs/tasks/README.md)；按影响读 [ARCHITECTURE](docs/ARCHITECTURE.md)、[RUNBOOK](docs/RUNBOOK.md) 和近期提交。
- 确认并行任务、基线与分支能力，必要时运行基础验证。简述目标、非目标、链路和验证计划。
- 连续小修改按需刷新，不反复通读全仓库。

## 规则

1. 按可验收功能分任务，一位负责人对结果负责，不默认前后端机械拆分。
2. 先找已有实现/扩展点；新增模块、框架、解耦、重构前说明现有实现为何不足。
3. 明确目标、非目标、验收；不扩大范围，不降低标准换取完成。
4. 修改前检查入口、上下游、数据、权限和并行任务。
5. 接口、权限、数据结构、模块边界、部署、重要依赖/团队规则变化，先写兼容/回退方案，由另一位成员异步确认，交付再审阅；Agent 不代替人的批准。
6. 沿用仓库格式、类型、锁文件、错误处理、日志和验证约束。
7. 验证匹配影响：相关检查、跨模块集成、关键用户流程端到端证据。
8. 如实区分未验证、失败、实现通过、合并、发布、客户验收。
9. 代码与受影响资料一起交付；一事实一处维护，其他位置引用。
10. 实际行为依据代码/运行结果，预期依据已确认需求/决策；不能改需求接受错误实现。
11. 按事件维护任务、架构、运行手册；合并/发布/重大阻塞由集成人维护全局摘要。
12. 同一任务持续记录结果、命令、失败尝试、阻塞和下一步，不保存聊天流水账。
13. 多人/Agent 用独立工作目录；文档冲突结合两边任务核实，不整份选一边。
14. 已接受 ADR 不重写历史，新增决定说明替代关系。
15. 不提交密钥或敏感原始日志；共享证据脱敏。

## 交付

`python3 .agent-context/tools/check_context.py --config .agent-context/config.json --base <基准SHA> --task <ID>`（Python 3.11+）；业务检查沿用项目命令。
规则、字段、CI/直接推送、文案豁免见 [DEVELOPMENT](docs/DEVELOPMENT.md)。
完成需要目标一致、验证证据及限制、相关资料、交接记录、关键变更人的批准。
检查器只能证明结构；Hook 可绕过；客户端读取和真实交接必须实际验证，不能只靠文件存在。
