# 插件内置 Video Studio 网页工作台

适用于 `0.3.0-web.35`。网页、后端、任务协议和启动器均在本插件内。Git 安装的完整操作说明位于源码根目录 `INSTALL.md`；本文件说明工作台当前行为，不要求重新安装另一套网站。

## 启动与数据

安装后可调用 `$open-video-workbench`，或在配置好完整 Python、Node.js 20+、FFmpeg/ffprobe 和实际 Codex CLI 的终端运行：

```sh
node <插件目录>/scripts/open-workbench.mjs
```

默认地址 `http://127.0.0.1:4317`。启动器核对版本、代码目录、数据目录及风格目录，只复用身份一致的服务；存在其他版本时明确报错，不关闭正在制作的任务。`open-workbench.mjs` 在后台运行服务；本目录 `start-macos.command` 使用前台终端，关闭该终端会停止对应实例。

用户配置和风格位于 `~/Library/Application Support/Video Studio/`，工作台项目、缓存、任务和桌面会话设置位于其 `workbench/` 子目录，默认交付根目录是 `~/Movies/Video Studio/`。安装或更新代码不覆盖个人数据。`VIDEO_STUDIO_HOME`、`VIDEO_STUDIO_WEB_DATA`、`VIDEO_STUDIO_PACK_ROOT`、`VIDEO_STUDIO_PYTHON`、`VIDEO_STUDIO_FFMPEG_DIR` 和 `VIDEO_DEMO_CODEX_BIN` 分别控制相应位置；不要填入其他电脑的路径。

## 首次配置

默认通过官方桌面队列把主制作任务交给用户选定的 Codex 桌面会话。新建专用会话，开启完全访问并完成一轮简短消息；确认 Video Studio、hosted ChatCut 和目标浏览器可用后，在工作台“读取桌面会话”，选择并“检查权限并保存”。这两项配置操作不启动模型。

开始制作前核对实际会话权限、占用、CLI 版本/参数和所选模型可用性；不自动更换模型。完全访问不代替系统、浏览器和网站授权。保持桌面应用、制作会话和 ChatCut 编辑器可用，尤其在本地导出期间。`VIDEO_STUDIO_AGENT_MODE=cli` 是明确选择的兼容路径，不作为权限失败后的静默回退。

只读环境前检区分 Python、媒体工具、下载器和具体来源依赖。运行 downloader bootstrap 只补独立 Python 下载环境；doctor 成功不等于远端 ChatCut 已连接。独立 CLI 等待 MCP 初始化，真实只读 `list_projects` 成功才作为 hosted 连接证据。已有登录/远端操作继续复用，不循环重装或重复生成。

Henry 风格使用已公开文本规范及真实媒体包。Git LFS 下载后通过 `styles link-pack` 登记完整源码包；缺失、LFS 指针和哈希变化阻止所选风格任务。未选用风格的缺项不阻止其他制作。详见[诊断说明](../references/diagnostics.md)。

## 当前一键制作流程

输入主题、时长范围、画幅、风格和音色 → 点击一键生成 → 同一主会话选材、写稿、设计与剪辑 → 客观预检 → 独立验收 → 正式交付或暂停修订。

新项目默认 60–70 秒并开启字幕；默认生成纯音乐配乐，只有明确关闭才省略。时长下限可以留空，历史项目只读，可查看和下载。实际视频流时长用于验收，不能靠重复、静帧、长停顿或音频编码尾部填充凑范围。

配置、风格与已保存音色选择不调用后台模型。官方/克隆目录查询、上传录音的克隆和生成任务在一键启动后执行；有效克隆需要授权和实际录音，保存成功后可复用。录音仅保存在本期 voice-references，不进入通用素材缓存或交付包。

主会话边核实资料、选画面、写稿与搭建可编辑时间线；已有可靠素材和事实优先复用，只补本期实际缺口，不设固定补搜轮数或素材数量配额。先用实际合成帧校准开头和代表性风格段落，再展开整片，避免到验收才发现整体风格偏差。具体规则见[连续制作](../references/continuous-production.md)。

方案、实际来源和风格设计通过同一会话的生产检查点保存，由宿主校验后返回当前方案/输入哈希。素材或文案需要修订时更新对应检查点，沿用原工程和未受影响音频，不新开全片制作。手动模式保留选材、审稿和明确批准入口，使用同样的素材、方案及质量规则。

## 修订与反馈

一键按钮下方常驻“修订与补充反馈”。AI 的具体替换提议和验收修复建议会预填，可编辑后确认。尚未回答的问题不会被下一条任务覆盖；旧方案、跨项目和重复提交的确认会被拒绝。普通继续按钮不代替替换批准。

“保存反馈”不启动模型，运行中也可以保存下一轮要求。确认后才开始修订，并保留原方案、候选、报告和用户要求。改变主题不会把旧反馈当成新主题的修改指令。

停止为协作取消，保留现有文件和远端操作 ID；工具尚未结束时仍显示占用，不能假装停止后立即重复派发。任务领取回执、实际桌面生命周期和最终结果共同决定状态；重启观察同一任务，不重复入队。

## 验收和交付

候选导出后保存实际临时文件。固定程序执行全片扫描、客观音频、真实词时间与字幕对齐、完整时间线和交付文件检查。已知未解决问题直接生成修订报告，不再花费一次模型审阅确认同一硬伤。

客观预检通过后启动独立验收会话。固定证据包统一绑定导出、字幕、方案和参考哈希；模型实际检查所有原定联系表、加密边界及必要原尺寸帧，并完成开头/中段/收束的真实试片风格对照。全局观察列表和每个问题只登记一次，报告整理由宿主完成，不能省略覆盖或放宽门槛。

允许无法实际播放和主观听审，但音量、峰值、静音、真实源音频到混音的位置、音画和字幕同步仍须检查。制作方自评不能作为独立通过；缺证据记未验证或失败。详见[制片与验收约定](../references/production-policy.md)及[验收方法](../references/quality-review.md)。

全部要求通过才登记正式交付，包括真实 MP4、3:4/4:3 PNG 封面、标题/正文/#话题 TXT，启用时 SRT，以及本次实际附属记录。不自动发布。

**验收失败立即暂停，不自动追加返工。** 页面提供标记“尚未通过验收”的临时文件和 ZIP，附工程方案、来源及问题报告。文件缺项明确显示，不能冒充完整合格包。用户查看后确认修订继续，或停止并保留结果；新导出重新绑定证据，旧结果不能替代本轮验收。

## 恢复和用量

右侧任务面板展示执行状态、工具事件、任务与项目累计 Token；失败和重试计入实际用量，未知值不填零。顶部“我的项目”保存与切换项目，素材缓存独立持久化；缓存线索不代替新热点的日期与事实核实。

技术中断后先核对现有工程、候选、导出任务和批准记录。待验收候选继续验收；已通过验收但本地复制失败只恢复交付，不重做视频。局部缺陷从修订入口处理，不以重新创建整个工程代替恢复。
