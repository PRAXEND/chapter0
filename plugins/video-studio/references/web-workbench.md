# 插件内置网页入口

网页代码与服务位于本插件 `workbench/`，由 [open-video-workbench](../skills/open-video-workbench/SKILL.md) 启动和打开。`scripts/open-workbench.mjs` 核对已有服务后返回实际地址，不依赖仓库外的 sites 目录。项目数据使用独立用户应用数据目录，或 VIDEO_STUDIO_WEB_DATA 指定的位置，不能写到插件版本缓存里。

# 网页制作工作台

网页宿主把用户实际点击映射为明确动作：选择本期风格与素材 → 生成和审阅文案及分镜 → 确认当前方案 → 调用 ChatCut 制作并导出 → 交付到指定文件夹。素材搜索与单条采集可在选材阶段独立调用。

`scripts/web_bridge.py` 是本地 JSON 适配器，使用同一套 `studio.py` 运行记录和风格库，不实现 ChatCut RPC，也不读取凭据。命令为 `python3 scripts/web_bridge.py <action> [--file /payload.json]`，结果输出 JSON。`catalog` 返回真实风格版本与插件信息；`create/sync` 建立或更新运行记录；`save-plan/approve/check-approval` 管理方案版本、哈希与明确确认；`inspect-media/verify-video` 校验实际媒体与最终文件。

## 点击与授权

- 网页搜索明确执行 `video-source-tools` 及其中适用的来源参考，读取本期风格快照并先保存 `material_plan`；不能用通用素材站搜索代替 skill 的来源策略。搜索只返回实际查到的候选内容与来源，不能伪造预览地址。同一事件的多来源合并展示；保留最多五项推荐、其他备选/暂缓、日期依据和未解决缺口。网页复选框负责实际选材，不重复打开宿主表单；推荐记录与用户选材分开保存。点击某条内容采集时，检查源页面对应的可用媒体，按本期预算有界获取，保留来源与源窗口。采集和选材不授权正式配音或剪辑。
- 风格卡片、规则和参考案例来自 `styles show` 与实际可选包文件；显示来源、版本、分析范围、证据限制和 unverified 状态，不追加通用推荐风格。浏览可选包不等于已导入；点击导入选用后才调用同一导入器，且不应用 profile_patch。原始证据仅可读取所选包/已导入包范围内的小型文本，不接受任意文件路径。
- 使用真实个人风格库；无条目时接受本次方向或不指定，不自动导入别人的可选包。
- 网页必须展示完整文案、逐镜画面/文字、来源映射与预计时间。默认确认事件由用户实际操作产生。用户明确委托 Agent review 并直接完成全流程时，可在审阅具体方案后登记 delegated_review，保留原始用户授权；不能伪称用户亲自点击，也不能把泛指做视频当作委托。用户也可在对话中明确表达对已展示方案的确认；记录 user_message 与实际原话，需要时记录先前审阅版本依据，不能冒充新的人工点击，也不能将泛指制作或未经确认的内容当作确认。制作请求必须携带匹配的方案与输入哈希。
- gaps 只用于实施当前提案必须具备但仍未取得的素材/事实输入；已经从文案中排除的未核实说法、不采用的完整故事需要的画面及按可见范围制作的边界归入 limitations，保存处理方式并随方案哈希固定。不能为绕过确认而删掉真正缺失的输入，也不能因此伪造证据或扩大结论。
- 改动本期规格、选材、素材字节、风格或声音选择后旧确认失效。仅改变交付目录不改变内容确认。常规实施时序调整遵循原 video-project 约定。
- 用户点击正式制作后持续完成已经授权的工作，保持可编辑 ChatCut 工程。不要用本地 FFmpeg 合成替代 ChatCut 剪辑和导出。真实缺失输入返回 needs_input，由网页展示，补充后先查询已有工程和任务。

## 本地缓存素材

网页同时持久缓存未采集的搜索候选，保存实际 URL、元数据、原检索和筛选记录；启动即可展示，历史搜索报告可回填，缓存元数据不下载媒体。用户点击某条候选才启动这条内容的采集，校验并保存真实文件后再显示为已下载，不自动选入成片。

网页本地素材库跨项目保留经过探测和哈希校验的真实文件，区别于尚未采集的候选链接。打开选材页直接展示缓存；搜索新内容执行 skill，本地缓存检索不调用 Agent。用户点击选用后才复制/登记到本期并勾选，不自动开始制作；新题材和风格应重新评估适配。旧采集的观察与许可状态继续保留，不因入库变为已核实。

## 本机项目

工作台每个项目分别保存于 `.data/projects/`。新建先保存旧项目，顶部「我的项目」可搜索和切换；切换前保存待修改方案，执行任务期间禁止切换，避免混用项目资料。素材缓存跨项目共享，选材、方案、确认、任务与交付保持项目范围。任务执行期间可查看步骤、素材预览、规则和项目列表；顶部显示实际任务和已用时间，修改本期、新建和跨项目切换须等任务结束，并明确解释。任务结束后自动恢复编辑，不以整页锁定代替进度反馈。

旧版本丢失的网页入口可从明确的本机任务/运行/交付记录恢复，必须重新核对已登记文件哈希；不编造旧任务成功、用户确认或未保存的编辑。

## 独立任务与恢复

网页每次动作可运行独立 Codex 会话，但不得忽略用户插件配置而丢失 ChatCut。任务之间靠运行目录、风格快照、批准方案、来源哈希与 operation 记录衔接，不依赖聊天记忆。

独立 CLI 会话的浏览器控制能力与 ChatCut 网页执行器连接是两件事。`Browser is not available: iab` 只能说明该会话不能打开标签页，不能单凭此错误判定已打开的工程无法导入或导出。恢复时先读取原工程与已有任务，按实际 hosted 工作流使用保持开启的同一工程；根据实际操作响应判定连接。确实缺少执行器时返回本次工程的真实干净链接、失败操作和明确步骤：打开本次工程、需要时登录、保持标签页开启、回到工作台继续原任务；不重建工程或重新审稿。

网页展示 Codex 实际上报的每次任务及项目累计 Token，包括失败与重试，缓存和推理分别作为输入/输出的子集，不重复相加。未上报保持未知，不能填零或用耗时估算。轻量 tokenUsageJobs 与项目一起保存，不随详细日志精简；历史只能采用现存真实记录，不编造丢失的统计。此统计不包含网页以外的聊天或 ChatCut 等服务额度。

取消本地会话不代表已取消远端生成。服务重启或任务中断后保留实际工程/资产/导出 ID，继续前查询未确定的 reserved/submitted 操作，不能盲目再提交。保持工作台显示真实工具事件，不用倒计时或模拟进度冒充服务进度。

## 交付

模型返回路径或 export queued 不算成功。必须实际找到 MP4、核对视频流、规格、时长上限、声音要求并完整解码；有字幕时交付实际 SRT。成片、脚本分镜、来源、工程链接与验收记录写入用户选定目录的新子文件夹，避免覆盖其他文件。

执行 studio.py audit 前，按实际时间线读回登记 run.beats 的 from_frame/to_frame、source_ids 和 visual_anchor；有旁白时登记实际音频资产与时长。不能把网页预计时段当成已核实的工程时序，也不能因为网页已有方案就省略插件分镜记录。

文件校验通过与感知验收通过分开显示。无法完整观看/听审的项目保持 unverified/needs_review，仍可交付实际已完成文件，但不声称全部质量项通过。


## 完整仓库候选与日期浏览

「更新仓库候选」读取当前插件所配置的 `chchenghuiguo-alt/video-daily` 每日仓库。网页服务不能直接使用聊天连接器，因此使用本机已连接的 GitHub CLI (`gh api`)，只读固定 commit 的目录、README、AGENTS、schema、manifest、post 和 meta；不运行仓库脚本。按实际目录读取全部 ready 批次，不限为编辑推荐的 Top 5 或单次搜索的数量。pending 批次显示上传中，读取失败逐项列出。此入口保留完整候选，不按本期题材预先排除；本期针对题材与风格的核实、去重和推荐仍由「按插件搜索素材」执行。

按原帖 `published_at` 在 Asia/Singapore 时区分组、排序和筛选近 3 / 7 / 30 个日历日（含今天）。收集批次、`collected_at` 和本机缓存更新时间另行显示；缺失发布日期进入「日期待核实」，不以批次日期代替。页面每次先展示 24 条，可继续查看剩余内容；本地缓存保留完整目录，刷新或新项目继续可见。

目录更新只读文字元数据；缩略图采用真实仓库图片地址直接显示，不把缩略图当媒体已采集或内容已核实。保存所有媒体的规格与来源哈希；点击某条才调用采集 skill 下载、校验实际文件。相同字节在新的仓库 commit 中仍可复用已下载文件。通用主题搜索每次最多 80 个来源，超出时明确检索范围和后续入口；视频下载来源数/秒数预算独立于候选浏览数量。
