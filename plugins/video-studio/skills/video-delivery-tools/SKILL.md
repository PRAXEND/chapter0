# 导出与交付工具

交付前按 [通用素材与构图流程](../../references/common-production.md) 确认 material_continuity 已实审；所有竖版还需 portrait_layout，绑定当前方案和导出。底部避让只用于竖版成片，3:4/4:3 封面沿用封面构图；辅助线不导出。保留内部原始出处，不仅因为补充画面来自其他事件而追加成片标签。

## 默认交付包

每期制作完成后，在本期输出根目录下建立 `YYYY-MM-DD_选题` 文件夹，放入以下四个实际文件。输出根目录沿用本期 `--output-root`，未指定时用 profile.output_root（默认 `~/Movies/Video Studio`）；工作 run 与交付文件夹分别保留在该根目录下。

```text
YYYY-MM-DD_选题/
├── 完整视频.mp4
├── 封面_竖版_3x4.png
├── 封面_横版_4x3.png
└── 发布文案.txt
```

日期采用用户本地时区的首次交付日期；优先使用会话时区，其次 profile.timezone，最后系统本地时区，不使用 UTC 日期代替。选题采用本期已确定的题目，清理路径分隔符和控制字符，保留中文。路径确定后记录到 run 内的 `delivery.json`，续做沿用；遇到不同作品的同名目录加 `（2）` 等后缀，避免覆盖已有文件。已有交付的改版也保存到新后缀目录并更新记录。

3:4 和 4:3 只约束封面，**不设置或改变视频的比例、分辨率或时间线尺寸**。本次明确要求可覆盖交付默认值；仅导出单个文件、验收或分析的任务按其范围执行。

## 成片导出

加载当前 ChatCut export 技能，读取实际项目、素材 readiness 和导出能力。输出规格来自本期 brief；调用 submit_export 保存真实 renderId，查询 track_export 直到完成。排队不等于交付。云端回退等路径遵守已有授权和费用约定。

获取实际 MP4 和本期需要的 SRT，记录文件位置与 SHA-256，保留可编辑项目链接。完整质量验收调用独立 video-quality-review；以最终导出为对象，不能仅看编辑器预览。

源转录或字幕修改后，核对外置 SRT 与最新 read_captions 的文字、条数、分页和起止帧；不能仅因导出成功就认为一致。发现差异先读回实际状态，再重新导出一次并复核。仍不一致时，保留两份原始导出和差异证据；可以从已与最终 MP4 边界帧核对的当前 Cards 生成配套 SRT，按本期 fps 将帧转换为毫秒，保留当前显示文字与分段。明确记录为由 Cards 派生的交付文件，绑定 Card revision、最终 MP4 与新 SRT 哈希；不要将它冒充未经修改的工具导出，也不要改画面字幕去迎合旧 SRT。抽查不能代替完整听审。

运行 `studio.py audit --run <run> --video <mp4> [--subtitles <srt>]` 做文件/规格校验并汇总各项有效审核；退出2表示待复核，不应无限重试。脚本、格式与恢复见 [运行记录](../../references/operations.md)。

## 封面与发布文案

为同一成片制作两张可用于发布的封面，沿用本期内容与视觉风格，分别适配构图、标题换行及留白，不拉伸同一图片凑比例。默认 PNG，建议竖版 1440×1920、横版 1920×1440；用户另有像素要求时仍核对准确比例。可采用成片合适帧或已有素材设计；需要生成或编辑位图时加载可用的 imagegen 技能。封面文字与成片事实一致，不凭空补充人物、产品能力或数据。

打开并查看两张最终图片，检查中文、专名、主体裁切、标题可读性和安全边距，并读取实际像素验证宽高比；文件名或生成提示不能证明比例正确。

`发布文案.txt` 使用 UTF-8，包含一条定稿发布标题、可直接发布的正文和可复制的 `#话题` 标签，例如以下结构（实际文件中填入本期内容，不保留占位符）：

```text
标题：本期定稿标题

正文：
用本期的具体反差、问题或观点引出话题，补足必要背景与观看理由。

话题：
#本期主题 #相关领域 #相关对象
```

正文的主要目的为抛出话题、钩子或观点，吸引读者观看和讨论。首句抓住成片中真实、具体的反差、后果、疑问或可讨论的判断；接着用简短自然的文字补足理解所需背景，说明这件事与读者有什么关系或值得看在哪里。按题材选择最合适的切入，不强制把话题、钩子、观点全部塞进一段。结尾有真实讨论空间时可留一个具体问题，不机械添加“你怎么看”。正文应能独立读懂，不重复标题、粘贴完整旁白或只写一句空泛口号；吸引力来自真实内容，不靠编造事实、夸大结果或假悬念。

标题、正文与标签均基于最终成片；平台已知时遵循该平台格式及篇幅要求，未知时给简短的通用版本，不为排版额外要求用户选平台。不将封面短标题自动当作发布标题，不堆砌无关热门标签。准备文案不代表获准代发。

## 交付核对

将最终 MP4 原样复制进交付目录，不用预览片段、代理文件或远程链接代替；复制后核对哈希与已验收文件一致。确认目录内四个文件均存在、非空且可打开，MP4 可完整解码，两张封面比例正确，TXT 的标题、正文及标签均非空且已定稿；正文有本期具体话题/钩子/观点，且与成片事实一致。`audit` 仅校验视频及审核记录，不代替封面和 TXT 的检查。

在工作 run 的 `delivery.json` 记录本次日期、时区、选题、交付目录，以及四个文件的绝对路径、字节数、SHA-256；封面另记宽高，并引用本次验收报告及未验证项。脚本/分镜、来源清单、工程链接、SRT 和验收报告留在工作 run，默认不混入这四个文件的交付目录；用户明确要求额外交付时再加入。

最终回复给出本地交付目录及四个文件的可点击链接，并说明必要的未验证项。缺少生成封面、观看/听审等能力时如实说明缺项或未验证范围，可交付已有文件，但不声称交付包完整或验收通过。修改成片后重新导出、验收，并核对封面与发布文案是否需要同步更新。
