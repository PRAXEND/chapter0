# 机器人资讯：多来源采集与 Top 5 筛选

主题相关补充遵循 [通用素材流程](../../../references/common-production.md)，与风格无关。主新闻仍按真实事件核实时效和排名；其他日期/事件的动作、场景等补充在候选池保留真实归属与适配边界，不冒充新的热点，不仅因跨事件就添加成片说明。Top 5 排名不排除补充候选，既有选材授权和下载预算仍有效。

当用户要求一轮近期机器人资讯素材收集时使用。按用户指定时间、受众、风格和本期目的执行；仅收集不自动扩展到制作、发布或定时任务。默认主动推荐最适合本期的 Top 5，并保存可回溯的筛选记录。

## 1. 定义本轮范围

按用户时区记录明确起止日期；“最近一周”未另有说明时为含今天的七个自然日，今天按已发生的时间计算。分别保留事件时间、原始发布日期、转发时间、仓库采集时间和本轮检索时间，不把本周转发当成本周首次发生。未给受众/风格时以清晰、真实、有画面支撑的机器人资讯为暂定标准，标明假设，不保存为长期默认风格。

读取或建立 run，先保存 brief、真实 selection、material_plan。采集阶段工具要求的技术参数仅是测试假设，不代表成片规格已获确认。已有素材与校验记录先检查，避免无必要下载。

## 2. 组合来源，建立事件候选池

1. 按 [X 仓库流程](robotics-x-repository.md) 读取范围内实际存在的 ready 批次、post/meta 和来源链。
2. 按 [企业官网与研究项目页流程](robotics-official-research.md) 回溯关键事实，补充对应型号的演示、产品图、公告与研究材料。
3. 按 [YouTube 流程](robotics-youtube.md) 补充本周新演示、发布会和视频缺口，并 probe 实际日期、时长与频道信息。

来源顺序服务于本期缺口，不要求每条事件机械查完所有网站。未找到研究热点时不拿旧论文凑数量。聚合网站仅作为线索；来源失败保留缺口，不补造事件或元数据。按实际内容与日期缩小范围，不无限搜索。

每条 source 保留真实 id、URL/本地路径、作者/机构、日期及依据、素材类型、时长/尺寸、原始或转载关系、授权与核实状态。对事实声明、素材技术状态和使用许可分别记状态。

## 3. 按事件去重与核实

为同一主体、型号、具体进展及时间建立稳定 event_id。X 原帖、官网公告、YouTube 演示若讲同一事件，合并成一个事件，保留各自 source_ids 与用途；同一公司的不同进展不合并。一场发布会包含多条新闻时，只有明确到具体内容/时间点才拆事件，不能仅靠标题扩充条数。

优先以原始视频 ID、原帖 ID、规范化 URL、相同文件哈希发现重复；不同编码或分辨率导致不同哈希不代表不同内容，需比较画面/来源。保留最完整的原始来源及更适合画幅的文件；跨日期旧素材在内部记录真实日期及背景用途，不因此自动添加成片说明。

核对：谁发布、何时发生、是新品还是旧内容再传播、事实还是厂商声明、实拍/仿真/模型生成/遥操作/自主是否明确。未核实的性能数字保留“厂商称”；未来试点不能写成已经落地。官方公告只能证明官方作出了声明，不能证明所有性能结论被独立验证。

## 4. 主动筛选 Top 5，并保存理由

用户希望每轮主动看到最有价值、可能成为本期爆点的五个事件素材组合。按事件排名，不把同一段视频的多个来源占据多个名额；不足五个合格候选就按实际数量推荐并说明，不以旧闻、夸张表述或未证实传闻凑满。

先将来源/日期明显不明、关键事实有冲突且无法说明、缺少支撑画面等候选列为暂缓或补证。重要但尚缺素材的事件可作为选题建议单独说明，不冒充可直接剪辑的素材。

逐项使用以下编辑判断（高/中/低/未知），不生成没有依据的精确流量预测或伪客观总分：
- 本期相关性：与主题、受众、风格和时间窗口是否吻合。
- 新意与影响：是否有具体新进展、能力变化、实际应用或行业意义；区分新公告与旧视频再传播。
- 画面表现力：动作是否清楚、变化是否直观、能否用短片段说明重点。没观看只能写待验证，不能凭标题宣称震撼。
- 讲述价值：是否有可信的对比、问题、结果或可解释的技术点，能形成准确的开场钩子。
- 证据可信度：原始来源、日期与关键事实是否可追溯；不确定性如何影响讲法。
- 素材可用性：是否有可获取文件、足够时长/清晰度、可裁切空间及许可信息。

综合判断排序，记录每条入选的主要原因、缺点、建议画面和推荐叙事角度；同分时优先证据充分、画面可用并能增加本期题材多样性的事件。已有播放/互动量只有来自可核对来源时才能引用，并注明采样时间；高互动不证明真实性，也不单独决定入选。可以提出“潜在吸引点”，不能保证爆款。

将筛选记录保存到 run 内 `selection-review.json`，作为素材采集附属记录，不新增未实现的 studio.py record kind。建议结构：

```json
{
  "scope": {"from": "实际起日", "to": "实际止日", "timezone": "Asia/Singapore", "audience_assumption": "本期实际假设"},
  "reviewed_at": "带时区的实际时间",
  "events": [{"event_id": "stable-id", "source_ids": ["source-id"], "date_evidence": "依据", "assessments": {"relevance": "高", "novelty_impact": "中", "visual_strength": "未知", "story_value": "高", "credibility": "中", "asset_readiness": "中"}, "evidence": ["可追溯链接或本地检查记录"], "decision": "top5", "rank": 1, "reason": "具体入选理由", "hook": "准确的讲述角度", "caveats": ["未验证项"]}],
  "top_event_ids": ["stable-id"],
  "supersedes": null
}
```

decision 使用 top5、reserve 或 hold；rank 仅给入选项。保留被合并 source 与事件对应关系，以及未入选理由。后续新证据改变排序时保存新版记录及修订说明，不冒充前一轮已知事实。用户没有确认时始终标为助手推荐，不把 manifest selected 或用户选择记录改成已批准。

## 5. 获取代表文件，区分验证层级

用户只要候选就不下载；要求收集素材时按用途、预算和推荐顺序获取代表文件，长视频优先选段，已有文件先核对再复用。记录“本轮新下载”“复用既有文件”“仅取得链接/元数据”“失败”四种获取状态。候选多时不要自动全量下载。

遵循来源专用流程校验文件。已下载、哈希匹配、解码通过、抽帧检查、连续观看、实际听审、事实核实和授权确认是不同层级；未做的不得标通过。未提供源哈希时本地哈希只用于固定文件。记录实际时长、尺寸、编码、音轨、来源区间和本地路径。

## 6. 表格、Top 5 预览与多选确认

表格后按 [选材卡片流程](material-selection-cards.md) 逐条展示真实预览与推荐理由，再弹出多选确认。预览、表格和表单使用同一批稳定 event_id 与相同排名；用户提交前保持“助手推荐”状态。

先给时间窗口、去重后的事件数、候选来源数、本轮下载与复用数量，再主动展示 Top 5：

| 排名 | 事件及原始来源 | 日期与口径 | 推荐理由／潜在吸引点 | 已有素材与获取状态 | 关键待核实项 |
|---|---|---|---|---|---|
| 1 | 实际标题及链接 | 原帖/公告/上传日期 | 有依据的具体理由 | 视频时长/图片规格；新下载、复用或仅链接 | 事实、画面或授权缺口 |

再列其余候选的简表（事件、素材、未入选/暂缓原因）。数量很多时在聊天中给 Top 5 和简要统计，完整候选及筛选记录提供本地文件链接，不隐藏暂缓项。附素材目录、检查记录与 selection-review.json，必要时简述最适合本期的组合。所有数量按真实记录计算，不把文件数、来源数和事件数混为一谈，不宣称这是全网完整热点榜。

2026-10-25 实测一轮读取 X 仓库8条候选、probe 3条 YouTube，并追溯企业公告和研究主页；下载两条 X 视频及一张图片，大小/哈希与仓库记录一致、解码通过，复用了已有宇树片段。发现旧开源事件再传播、未来试点被误写成已落地等风险。此记录验证组合采集路径；Top 5 排名是本次新增的编辑与记录要求，不能把历史候选表称为已经做过这套排名。
