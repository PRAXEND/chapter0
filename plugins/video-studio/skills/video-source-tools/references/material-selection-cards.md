# 采集后选材卡片

主题相关补充遵循 [通用素材流程](../../../references/common-production.md)，与风格无关。主新闻仍按真实事件核实时效和排名；其他日期/事件的动作、场景等补充在候选池保留真实归属与适配边界，不冒充新的热点，不仅因跨事件就添加成片说明。Top 5 排名不排除补充候选，既有选材授权和下载预算仍有效。

用于素材采集完成后的交付：先看 Top 5 的预览和推荐理由，再一次多选确认。仅展示推荐不代表用户已经选定。明确要求仅列表、已经选定或授权自动选材时，采用当前指令，不额外设置确认关卡。

## 先展示预览与依据

从本轮已去重、核实、排序的候选中取最多五项；机器人资讯以事件为单位，关联其 source_ids，其他题材以实际素材或素材组为单位。不足五项说明原因，不凑数。

每项使用一致的编号与标题，并展示：
- 真实视频预览、代表帧或官方图片；注明是片段、抽帧还是封面，以及对应 source_id、源时间范围（可得时）。
- 一到两句具体推荐理由、适合本期的讲述角度。
- 原始出处、日期、已获取/仅链接状态，以及事实、技术或授权方面的关键限制。

使用当前宿主支持的媒体展示方式；Codex 中已有本地媒体用绝对路径展示。优先复用已获取文件和预览，不为了展示绕过下载限制或把全部候选下载一遍。仅有封面不能宣称已观看视频；预览不可用时明确写“暂无可用预览”，提供可访问的来源链接作为回退，不伪造播放器、缩略图或生成替代画面。

## 再弹出一个多选表单

实际执行时加载当前安装的 ChatCut `widget-forms`，发现并读取 `ask_followup_questions` 的实时 schema。Codex 使用交互式卡片；其他宿主按该技能适配，不输出只能在 ChatCut 内渲染的原始 widget 标签。

当前 Codex 表单的视觉预览选择器是单选，因此采用“聊天内预览 + 文字多选”两步展示，不把 `variant:"visual"` 当作已验证的多选预览能力，也不要求逐条进行五次单选。

表单包含一个必填 `type:"multi"`、`variant:"default"` 字段，id 为 `selected_materials`，标签为“请选择本期要采用的素材（可多选）”。每个选项的 id 使用稳定 event_id 或素材组 id；label 为“排名｜事件或素材标题”，与上方预览一一对应。推荐理由放在预览区，普通选项保持简洁。不预选推荐项，不绑定会直接修改项目的 onSubmit 动作。

最后增加 `id:"__other__"` 的选项，标签“调整候选或暂不选择”，让用户输入换一批、补充来源、从完整候选中选择或暂不采用等要求。提交按钮写“确认选材”，messagePrefix 写“本期素材选择：”。无需仅为选材新建 ChatCut 项目或启动剪辑。

先完成预览、推荐理由和记录保存，再调用表单；调用后等待提交结果，不把超时、默认推荐或未提交状态当成选择。工具不可用时说明交互表单暂不可用，保留同编号预览，让用户用“选 1、3、5”等文本确认。不要声称已经弹出了不存在的卡片。

## 保存选择并衔接后续

展示前在 run 中保存 `material-picker.json`：本轮 round_id、展示时间、推荐记录路径、每项稳定 id、排名、标题、source_ids、预览路径/URL、预览类型/源区间、推荐理由、限制及 `status:"awaiting_selection"`。没有 run 时先按 video-project 建立采集记录；这些是 run 附属文件，不新增 studio.py 不支持的 record kind。

收到提交后，用本轮保存的 id 映射解析选择；仅返回标题时也必须唯一对应，不凭已变化的排名猜测。将用户原始答复、确认时间、selected_ids、对应 source_ids 和本轮 round_id 写入 `material-selection.json`，并更新 picker 状态。新版候选保留新 round_id，旧选择不自动套到新版。

若选择调整候选或暂不选择，按其说明更新候选或停止选材；与素材选择同时提交而意图不明确时，只澄清冲突，不直接开始制作。用户选择本身仅确认采用范围：已有制作授权则继续文案、分镜等下一步；原任务只是收集则交付选中清单。不要把素材选择写成与其无关的题材 selection 或发布授权。

本流程依据当前表单工具与宿主技能定义；文字多选和预览组合尚需在实际采集任务中验证显示与提交，不将文档校验称为交互实测。
