# 视频项目与技能组合

新制作默认一键自动模式，按 [连续制作](../../references/continuous-production.md) 在同一主会话边选材、写稿、设计和剪辑；最后独立验收。先读 [共用自动制片与独立验收约定](../../references/production-policy.md)，工作台和聊天使用同一真实上下文与质量规则。收齐主题方向、时长范围（可设下限）、横/竖版、指定风格和具体音色后，AI 自主选题、选材、审阅方案、制作与验收；仅在用户明确要求逐步审稿时采用下方手动确认分支。新项目 brief.requirements.review_policy=sampled-objective-v1。音色在采集前解决；完整制片必须委派独立验收子 Agent，验收失败提供完整临时交付并暂停，用户确认具体修改后才继续；正式交付仍须全部验收通过。

选用 henry-hot-news 或 henry-technical-explainer 时，在搜索、分镜和制片前运行 `preflight --capability python --capability media --style <当前 selector>`；网页已执行同一检查。所选风格素材缺失先按结果补齐，不能跳过参考或把 LFS 指针当媒体。使用检查返回的 packRoot 解析 resource: 路径，位置登记与补齐方法见 [诊断说明](../../references/diagnostics.md#可选风格包git-lfs-与素材完整性)。不改风格版本、用户偏好或既有方案确认。

新建聊天项目也在 brief 中写入 workbench_rules=2、generate_music=true，只有用户明确关闭才设为 false。字幕默认开启。已选具体音色写入 requirements.voice；沿用指定音色，参考片只影响表达。旧项目只读，可查看既有结果。新项目导出前按 production-policy.md「新项目的声音与字幕」核对配乐和字幕；聊天无工作台提交入口时，使用实时目录中与已选身份完全相同的音色调用正式配音。

所有项目先读 [通用素材与构图流程](../../references/common-production.md)。无风格项目也保存 productionPlan、每镜 sourceUses 与 layout，并通过 `record --kind production_plan` 登记；网页保存会自动登记。先检查重复动作、规划相关补充，再按实际画幅安排构图。所有竖版采用本期 portrait_bottom_inset（默认 18%），关键画面与字幕共同上移；横版/方形不套用。通用记录纳入原有方案确认及验收，不写入个人风格库。风格中的构图意图在这项通用避让边界内适配具体坐标。

插件根目录为本技能上两级，命令入口为 `scripts/studio.py`。本技能只组织工具，不规定题材、语言、时长、视频比例、音色或剪辑模板。

网页宿主发起的选材、审稿和制片请求，按[网页工作台约定](../../references/web-workbench.md)读取真实运行目录、确认哈希与任务记录；适配器是 `scripts/web_bridge.py`。独立会话不重置项目，不把网页保存/选材当作制片授权；实际点击一键生成保存的自动授权有效。

用户要打开或在网页中操作工作台时，使用 [open-video-workbench](../open-video-workbench/SKILL.md) 启动插件内置页面；打开页面本身不开始制作。

## 需求与风格

先读 `profile`、`styles choices`；完整展示 options 中已导入和可导入的当前风格，历史版本分开列出，读取错误如实说明。聊天与网页共用目录；个人库为空不表示没有可用风格。具体浏览及显式选用命令见 [风格选择流程](../../references/style-selection.md)。继续项目时先读 `status --run`。已说明的题材、参考和要求直接采用。用户尚未提供题材时只询问题材/目标；允许用户委托选题。热点任务再联网核实事件时间，普通题材不套近72小时窗口。

`profile.production_preferences` 保存用户明确要求的讲述、音乐、交付和协作习惯，按当前任务读取；不作为新安装的模板。需要选择按钮时按 [个人风格选择](../../references/style-selection.md) 从真实风格库展示单选卡片，用户已指定则直接采用。

风格可以是库中名称、自由描述、参考脚本/视频，或不指定。展示库中实际存在的名称、描述、版本与未验证状态；不预装推荐模板。用户给出风格名称时匹配真实条目；重名要消歧，不能凭相近名称代选。自由描述可仅用于本次；用户要求保存、复用或明确“记住此风格”才调用 `learn-video-style`。仅分析参考不意味着要保存。

选择已保存风格后用 `styles show --selector <id@version>`，实际读取返回的 SKILL.md 和 production-context 的 style.guide（全部规则）；具体组件源码再按需从 style.json 读取，与本插件工具技能组合使用。每次新聊天都查目录，不依赖聊天记忆；不存在的风格说明缺失，不编造规则。未指定风格且没有用户保存的 default_style 时可按本次需求创作，不把这次选择自动存成默认风格。

建立 brief：题材、目的/受众、输出规格、语言、时长范围（需要时）、旁白/字幕/声音要求、风格或 null、用户覆盖的规则。只问影响成片的缺项，可按使用平台给出合理建议并注明假设。用户当前要求 > 本期风格覆盖 > 选择的风格 > 用户保存偏好。格式限制来自实际工具能力，不来自旧模板。

选定风格明确默认画幅或尺寸时，在用户未覆盖的情况下将其落实到 brief.requirements.width/height，并用于项目时间线及最终导出；不能只在描述中写竖版却沿用参考母版的横版尺寸。该默认值只作用于所选风格，不改成全局视频偏好，也不影响封面比例。

通过 `new --title ... --brief ...` 保存；参考 [记录格式](../../references/operations.md)。选择风格会在 run 内保存不可变版本快照。续做读取快照；库里新版本不会自动替换它。

## 制作检查点与手动审稿

手动模式顺序：收集素材 → 确认选材 → 提交文案与分镜 → 用户确认 → 配音和剪辑 → 验收与交付。选材确认、音色选择或泛指“做一个视频”不等于确认尚未展示的文案与分镜。用户本次明确要求跳过方案确认或直接按其已确认方案制作时，尊重该指令。

正式配音前保存当前完整文案和简洁逐镜头分镜表；自动模式允许边采集边搭可编辑粗剪，下面的方案是同一会话中的检查点，不是独立串行阶段。分镜表包含镜号、预计时间段、旁白/屏幕文案、对应素材与来源片段、画面内容及裁切/字幕/转场意图；手动模式交给用户审阅，自动模式在同一制片会话中自行审阅并记录依据。无旁白视频也保存屏幕文字与画面安排。标明总预计时长、素材缺口和关键事实口径；预计秒数是规划值，不能冒充已生成音频的实际时序。

选定风格时按 [风格到分镜的落实方法](../../references/style-storyboard.md) 保存结构化 style_plan：逐条关联规则与镜头，区分核心表达和条件手法，并为实际动效记录用途、触发、变化、时长、位置避让、声音、实现与替代。分镜前读取相关复现配方和代表节点，检查整片变化与核心表达；不能把全部节点简化为同一种标题入场。仅有脚本规则或未选风格时不强制动效。网页与对话采用同一校验，完成这些设计再提交现有的一次方案确认。

将方案保存为 run 内带版本的 `script-storyboard-vN.md`，并以附属文件 `script-storyboard-approval.json` 保存版本、文件哈希、状态 awaiting_confirmation。手动模式展示方案后请求“确认按此制作”或修改意见；自动模式由 Agent 审阅具体方案，并按本期自动授权记录 delegated_review 后继续，不等待人工审稿。可加载当前 ChatCut widget-forms，用单选表单收集确认/修改，也可接受明确文字答复。手动模式等待来自本技能的审稿约定，不冒充用户另提要求；已有明确跳过/直接完成的授权则记录原始指令并继续。未收到所需确认前可继续素材核实与整理，不生成正式配音、制作 MG 或写入正式剪辑时间线。

审阅完成后记录对应版本、哈希、时间和实际审阅依据，状态改为 confirmed；续做读取该记录，不重复索要同一版本确认，也不把超时或未答复当成确认。不新增 studio.py 未实现的 record kind。确认后按真实音频和素材调整镜头时长、修正错字等常规实施无需重审；改变主要文案含义、事实口径、事件取舍或叙事顺序时，保存受影响段落的新版本，自动模式在原主题和授权边界内自行重审，手动模式请用户确认。用户直接提出的局部修改可按其要求执行，不自动重开全片审稿。

## 按任务加载工具

- 缺依赖或首次配置：`setup-video-studio`。
- 查资料、选材、下载、检查来源：`video-source-tools`。
- 项目、导入、镜头、MG、转场：`chatcut-edit-tools`。
- 配音、音乐、字幕、同步：`video-audio-tools`；正式 TTS 前先解决音色。没有可用克隆且尚未选择时，先询问是否克隆；已有有效选择直接复用。
- 完整声画验收、问题定位与修复复查：`video-quality-review`。
- 导出、两版封面与发布文案交付：`video-delivery-tools`。

完整制片默认交付到本期输出根目录下的 `YYYY-MM-DD_选题/`：完整 MP4、3:4 竖版封面、4:3 横版封面、含发布标题、正文及话题 tag 的 TXT。正文用于抛出与本期内容相关的话题、钩子或观点，吸引观看与讨论。开始规划时纳入这四个文件，成片定稿后同步完成；具体命名、像素与校验见交付技能。两个比例仅用于封面，不影响 brief 中的视频规格。制作记录留在工作 run；本次明确的交付范围优先。

先用题材与风格共同形成 material_plan，再找素材：题材限定内容真实性和对象；风格确定景别、运动、留白、动作长度、同期声等采用标准。已有素材先评估缺口，不为完成表格重复下载。参考视频的素材不自动成为新片的素材。

每段记录叙事目的、来源或生成资产、画面意图、真实时间范围；有事实主张才需要对应事实来源，有旁白才需要真实音频时序。纯画面、长镜头、静帧、无配音、横屏等均可由本次要求决定。

文案与分镜已确认、制作已获授权后持续完成，不额外强制逐阶段批准。仅要求方案/分析时交付方案/分析。恢复未知外部任务先查实际状态，操作去重见运行记录。未请求发布或定时执行时不扩展任务。
