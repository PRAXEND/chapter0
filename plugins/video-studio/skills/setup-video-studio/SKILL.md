# 配置工具

插件根目录为本技能上两级。运行 `scripts/studio.py doctor`，只在需要下载功能时安装下载器：`bootstrap` 使用独立虚拟环境。系统 Python 损坏时用宿主可用的完整 Python 3.10+；不把开发机路径写入技能。macOS 为当前支持平台。

## 工作台 CLI 兼容检查

工作台启动任务前用实际 CLI 的绝对路径检查版本、登录、必需执行参数，并通过只读 app-server 的 config/read 与 model/list 核对同一工作目录的模型配置和可用目录。遵守显式 VIDEO_DEMO_CODEX_BIN；未显式指定时可选择 PATH 或已安装官方应用内的较新兼容 CLI。版本基线只代表工作台支持范围，模型仍以该 CLI 的实际目录与服务错误为准，不能把“可以 --version”当成模型兼容。更新后重新检测，保存本次实际路径、版本、模型，不擅自降级或替换用户模型。

遇到 requires a newer version of Codex 时立即停止该调用，提示升级实际被选中的应用/CLI 后复检，不循环重试相同版本。检测不得创建线程、启动模型任务或修改 Codex 配置。素材前置检查与依赖补齐沿 video-source-tools 的实际能力范围执行。

## 依赖插件检测与安装引导

ChatCut 是剪辑、配音与导出的必需集成；Video Studio 自带的 `chatcut-edit-tools` 只是使用说明，不代表 ChatCut 已安装。其他插件仅在当前任务实际需要时发现，不预设额外必装清单。

先查当前会话工具和可用技能。已发现 ChatCut 时，读取其实际安装的 `chatcut-plugin-basics`，按其说明调用只读工具验证认证与服务响应。若工具未加载，可通过宿主插件列表或已安装技能定位安装状态；工具缺失只表示当前不可调用，不能单独据此断定未安装。不读取或展示令牌，不重复建立另一个 ChatCut MCP。

缺少依赖或无法确定安装状态时，使用宿主 Plugin Management 的 `search_plugins` 搜索精确产品名。先发现工具并读取当前参数，不硬编码插件 ID、市场名、服务地址或安装链接：
- 有明确、可安装且尚未安装的匹配项：用 `suggest_plugins` 提供该结果的真实安装入口；这是安装引导，不代表安装完成。已有安装请求授权时继续受支持的安装步骤，不重复索要同一授权；账户登录或交互授权由用户完成。
- 已安装但未连接：使用该插件提供的连接入口或登录指引。若工具需要新聊天才能加载，说明新建聊天后再次调用本技能验证，不报告已连接。
- 搜索无结果：明确“当前插件搜索未找到”，提供宿主插件目录（ChatGPT 为 https://chatgpt.com/plugins），请用户提供发布者的安装链接或 marketplace 来源；不能据此断言该服务不存在，也不猜测来源安装。
- 用户提供本地或 Git marketplace 来源时，先检查来源清单与插件身份，并读取本机 `codex plugin marketplace add --help` 和 `codex plugin add --help`。在已获安装授权的范围内注册该来源并安装清单中实际存在的插件，保留现有连接与配置；使用参数数组或正确引用路径。没有安装授权的纯检查请求只给出安装入口。
- 宿主没有搜索或安装能力时，明确能力缺项，并给出可用的官方入口或请求发布者来源，不伪造已执行步骤。

安装后重新核对插件启用状态和工具可用性，再调用真实只读工具验证。区分“待安装”“已安装待加载”“待登录”“连接验证失败”和“连接已验证”；网络错误保留原始原因，不归为未安装，不循环重装。

需要保存分层诊断或断点清单时，按 [连接检测与断点恢复](../../references/connection-recovery.md) 将本次真实只读结果写入 `studio.py connection`。它不代替 MCP 调用，也不修改 run/revision 或重新提交任务。

工作台独立 CLI 会话必须等待 MCP 工具初始化：启动参数使用 `-c mcp_optional_startup_grace_ms=0`，沿用每个服务已有的启动时限，不写入用户配置或新增同名连接。若旧版会话提示 hosted ChatCut 工具未加载，先更新工作台执行代码并用同一执行入口实际调用 `list_projects` 验证，再复用原 run、有效确认哈希和已有远端记录继续。不要将工具缺失当成要求用户重新审稿的理由；若初始化实际失败，保留具体错误并按 ChatCut 基础技能诊断。

汇报分别列出本地环境、依赖安装、认证/连接和下一步。只有本地检查通过且必需依赖实时验证成功，才报告制片环境就绪。`doctor` 的 `local_ready` 仅表示本地工具就绪，不能证明 ChatCut 或远端生成额度可用。仅在当前制作请求明确需要其他插件时复用上述流程。

## 网页插件连接与首次体验

默认引导 ChatCut 网页插件；同机安装 ChatCut Desktop 不代表网页插件已连接，也不是切换到 Desktop 的理由。用户明确指定 Desktop 时遵循其选择。保留已有插件、MCP 连接及工作区未提交修改，不通过移除其他连接解决工具加载问题。

安装入口解决插件安装，实际连接步骤遵循已安装的 `chatcut-plugin-basics`。在 Codex 中，工具缺失时用 `codex mcp get chatcut` 检查已有注册；已有注册就复用，确实缺少时按基础技能的当前说明注册。需要认证时引导 `codex mcp login chatcut` 并由用户完成登录。登录成功不等于当前聊天工具已加载；仍缺失时按基础技能收集连接诊断，必要时提示新建聊天后验证，不重复安装或反复登录。以网页插件的 `list_projects` 等真实只读调用成功作为连接验证依据，不以 Desktop 工具或本地 doctor 成功替代。

首次安装引导完成且用户希望开始体验时，按基础技能创建空项目（未指定名称可用“我的第一个ChatCut视频”）；继续既有项目时使用用户指定的项目，纯检查或重复 setup 不自动创建项目。使用返回的浏览器交接 URL 在内置浏览器打开编辑器，按用户语言本地化路径并保留交接参数；将标签页保留给用户，直接分享的链接去掉内部交接令牌。具体浏览器工具随宿主发现，不依赖固定的 Node REPL 或外部浏览器实现。

简短介绍可做视频剪辑（语音内容清理、字幕、转场和补充素材）、MG 动画制作，以及视频、旁白、音乐和音效生成；再询问用户已有素材、想做的视频类型、时长与发布平台，只补充尚未明确的信息。说明用户也可以进入 ChatCut 编辑界面自行调整时间线、字幕和 MG 动画。需求明确前不发起付费生成；已经给出明确制作需求时直接衔接 `video-project`，不重复问卷。

## 偏好与迁移

`profile` 返回用户配置；`profile --merge-file <json>` 只更新指定字段。新安装没有默认题材或创作风格，不默认男声、语言、比例或目标时长。当前项目规格放在 brief；用户明确要求记住的偏好才存 profile。首次实际需要 TTS 时沿 ChatCut voice 技能试听具体音色，筛选条件来自用户。

风格库由 `styles list/show/add` 管理。用户要求设置默认风格时保存 `default_style:"id@version"`；清除用 null。个人库位于 Video Studio 状态目录，升级代码不覆盖。

旧版 Robot Video Studio 配置不自动导入：其 style/creative 和默认输出可能是旧模板而非用户决定。仅在迁移任务中读旧配置，将用户实际确认的 voice、输出目录等按当前要求逐项写入新 profile。旧 run 使用原版继续；不要将 schema_version 改数字冒充迁移。

环境变量：`VIDEO_STUDIO_HOME` 修改状态根；`VIDEO_STUDIO_FFMPEG_DIR` 指定 FFmpeg 目录。说明实际完成的检查和缺项；若已要求制片，继续 video-project。
