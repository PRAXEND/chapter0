# 首次配音与音色恢复

仅在本期需要 TTS 时执行。先读取当前 ChatCut voice 技能和实际工具参数。风格、配音方向或制片确认不等于选择某个音色，也不授权克隆。

1. 从本期已确认选择、run 中音色记录和 `studio.py profile` 读取用户已选音色。用当前账号的 `manage_voice` 实时解析实际 `(provider, voiceId)` 与就绪状态，不用显示名称匹配，不复用易失 voiceRef。有效的已选克隆或官方音色直接继续，不重复询问。克隆音色不因目标语言不同而被排除。
2. 没有有效选择时，查询当前账号的真实音色目录，确认自定义音色是否存在、是否就绪（分页时读全自定义列表，不用筛选后的空页判断）。查询失败是连接问题，不是“没有克隆音色”；说明实际原因并保留记录。历史音色已删除或不可用时说明原因，再进入选择。
3. 账号没有可用克隆音色，且本次未明确选择官方音色或克隆时，先问：“你还没有可用的克隆音色，需要克隆自己的声音吗？”提供“克隆我的音色”和“选择官方音色”。这是本工作流针对首次使用的分支，优先于通用 voice 技能直接展示混合音色的默认路径。已有多个可用克隆但没有已确认选择时，按 voice 技能展示真实、可试听的音色供用户选择，不替用户猜测。
4. 选择不克隆：用实时返回的官方目录，结合用户的语言和声音方向展示 2–4 个候选的名称、简短特点和真实试听。等待用户选中具体音色才调用 TTS；不能把第一个候选、推荐或超时当成选择。已明确选过官方音色的用户不重复询问是否克隆。
5. 选择克隆：先调用 `manage_voice voiceType="custom" action="check-create-access"`。账号无创建资格或名额时说明原因，提供改选官方音色的入口，不先收集录音。可创建时，收集未提供的名称、10 秒至 3 分钟录音（建议 30–60 秒干净独白）、不超过 100 字的试听文本与完整明确的授权。录音格式、授权原文、导入及 clone 参数按当前 voice 技能执行。上传文件或选择“需要克隆”本身不是完整授权。外部 Codex/网页工作台不输出原生编辑器专用的 `<clone-voice/>`。
6. 已有本次明确提供的录音及授权时复用；缺什么只问什么。得到授权后通过 ChatCut asset-import 导入录音，使用真实音频 assetId 调用 clone。成功后展示返回的试听并使用实际就绪音色。若失败，保留本地录音、已导入 assetId 和任务状态，不重新要求录音、不重复创建；先核对已有声音/任务再恢复。

选择与来源保存到 run 内 `voice-selection.json`，包括真实音色身份、用户选择依据、录音哈希（如有）、实际 assetId/任务 ID。用 `studio.py operation` 保留克隆提交记录；克隆意图绑定录音哈希和本次输入记录，不因重复“继续制作”而再克隆。音色解决后才进入正式配音。只在用户明确要求记住偏好时更新 profile，本期选择不覆盖个人默认音色。

录音保存在本期 `voice-references/`，不加入视频选材、共享素材缓存、风格包或交付文件。ChatCut 会保存克隆源录音供后续服务迁移，提交前向用户说明。检查与试听不等于克隆成功；以实际返回的就绪状态为准。

## 网页工作台交接

制片任务是独立 CLI 会话，不能在其聊天里等待输入。缺少音色决定时返回 `status=needs_input` 和结构化 `voiceRequest`；一般连接问题仍用 `questions`。不在等待期间提交正式 TTS。

- `clone_choice`：先问是否克隆，候选数组为空。
- `voice_choice`：候选必须来自本次实时查询。每项包含唯一 key、name、summary、可播放 sampleUrl、内部 provider/voiceId、voiceType（official/custom）；不能编造或暴露内部身份到可见文案。
- `clone_recording`：仅在创建预检通过且本次还没有录音/完整授权时返回；网页收集名称、录音、试听文本和默认未选中的授权。已收齐但调用失败时返回一般 `needs_input`，复用 `voice.answers` 的录音和授权，不能重新返回空录音表单。
- 不需要输入时 `kind=none`、message 为空、candidates 为空。

`context.voice.savedVoice` 是待实时验证的用户偏好，`context.voice.answers` 是与当前方案绑定的、服务器记录的明确输入，按时间顺序读取；最新选择优先。`action=official` 表示下一步应返回官方试听列表；`action=clone` 表示执行创建预检；`action=select` 包含实际选中候选；`action=recording` 包含录音路径、哈希、名称、试听文本和完整授权。它们是已取得的输入，不重复提问。返回新请求前先检查已完成的 `voice-selection.json` 与操作记录。

工作台会保留当前方案确认并恢复同一个工程。只补齐音色输入不需要重新审阅文案；用户另外改变文案含义时才按文案确认流程处理。
