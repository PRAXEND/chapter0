# 开场、布局与节奏复核

新片和重剪都读本参考。目标时长是预算，不能靠空档、循环原片或长卡片凑满 90 秒；在用户允许的范围内，以信息与完整动作决定实际长度。

## 开始剪之前

- 把最具体的动作、数字或矛盾尽早交给观众，通常前 3 秒应已看见本期看点。厂商规格/目标的限定随数字一起出现。开场是否有效由实际画面判断，不靠标题里出现数字自动认证。
- 横屏改竖屏要逐镜决定：主体特写可放大，跨画面搬运/双手操作要保留全景；必要时用同步局部放大窗。不要整片一律缩成中间窄条，也不要一律 cover 裁满。字幕、来源条和标题应与主体共同排版。
- 按实际源动作与语义分配镜头：保留拿起、运送、放下、松手等相关动作终点；完成后删掉无信息的回走或等待。纯解说章节间通常不需要数秒空档。有信息的现场声或动作展示可以例外。
- 图解在讲到数据时才出现，关键值尽早可读；避免先放数秒空坐标/空进度条。简单对比优先短图解或叠加在相关画面上，不能将每一段解说都铺成卡片。
- 回看应带来新的观察点，例如放大接触、慢看释放、对比前后。单纯加“回看”字样不使重复蒙太奇合理。检查原片内部切点，避免裁出首尾几帧残片；相邻两个片段若实际连续展示同一镜头，按连续观看结果判断。

## 自动扫描及人工判定

`studio.py audit --evidence ...` 自动生成 `editorial-check.json`，也可单独运行：

```sh
python scripts/review_edit.py --evidence final-evidence.json --output editorial-check.json
```

复用配乐检查的完整 timeline/voice_sources 证据，指定真实 `narration_tracks`；`visual_tracks` 指主画面轨（默认 V1），不要把全程来源条当成长卡片。可提供 `source_cuts`（asset ID → 原片切点秒数），按内部镜头而非外层素材长度计算长镜头。

扫描规则是定位线索：内部旁白停顿 ≥1.5 秒、主画面连续镜头 >8 秒、非同时播放的同源区间重叠 ≥1.5 秒且占较短区间 ≥50%。这些不是强制切镜节拍，也不是质量评分。同步放大窗不会被当作后续回放。缺失/部分 ASR、时间线分页不全返回 unverified。

候选 ID 保留在报告中。检查像素后，在最终证据的 `editorial_review.resolutions[候选ID]` 中记录 `decision: "keep"`、具体 `basis` 和已查看的 `frames`，才能保留有意义的完整动作或解释性回看。不得填写笼统“已检查”。另记录 `editorial_review.opening` 和 `.layout` 的 basis/frames，覆盖真实开头、不同布局、裁切与最长字幕。缺少这些证据仍待复核；改时间线后重新扫描并重做受影响判断。报告绑定最终 MP4、证据哈希和 run revision。

最终 `editorial_rhythm` 审阅必须回答：开头是否立即兑现看点；竖屏布局是否有效利用空间且保住关键动作；长停顿是否有可见理由；重复画面是否增加信息；图解与字幕是否给足阅读时间。不得用技术规格通过代替这些判断。

## 导出前后

1. 语义重排使用 ChatCut Script，只提交本次要改的轨道；预览必须确认没有意外重建其他有原声转录的 B-Roll。保留已接受的克隆录音可避免无必要的音色重生成。
2. 重新读取当前时间线、最终词时间、Caption Cards；刷新字幕后检查静默时字幕是否退出。云端一次批量预览可能出现加载中的白帧或旧字幕，须重取疑点帧，再以实际导出像素判定，不能忽略疑点或仅凭首张错误截图重剪。
3. 逐项对照导出 SRT 与当前 Card。若刷新后仍有分帧差异，先保留原始 SRT 和差异记录，再核对成片切换帧。只有确认烧录字幕使用当前 Card 边界时，才可按这些边界确定性重建交付 SRT；不得编造词时间或只改外置字幕来掩盖烧录错误。
4. 时序修改后必须重新扫描最终混音中的旁白停顿。保留原纯器乐时优先调整稳定低音量及淡入淡出，不能因为有音乐就默认自动压低。实际听审不可用时明确标记，音量扫描不等于听过。
5. 在当前导出字节上做解码、黑场、字幕边界、切点和动作终点检查。完整播放、抽帧和听审分别记录；缺哪项就如实保留哪项未验证。

## 已验证的 Digit5 修订方向

把“工作90分钟/充电9分钟”的厂商规格移到开头；复用原克隆录音，压缩章节空档；删除结尾重复蒙太奇；纯图解由14秒缩至约7.6秒；主体镜头放大，跨幅搬运保留全景并增加同步松手细节窗。用这一案例说明取舍，不将其镜头数、版式或绝对音量写成所有视频的固定模板。
