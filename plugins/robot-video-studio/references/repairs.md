# 局部修复与复验

这些方法在首条真实样片的 2026-10-16 修订中验证。参数是案例，不是所有语音的固定预设。先读取当前 ChatCut 工具说明；接口更新后优先使用正式支持的能力。

后续 2026-10-17 修复了旁白停顿处的配乐突然变响，参见 [自动检查、稳定电平修复与回归结果](music-pauses.md)。有 BGM 的后续新片和修订都执行该检查，不能只沿用下方第四版的自动压低设置。

## 声音突然变慢

先区分源配音表现、剪辑播放速率和导出故障。读取问题段及相邻段的 asset 生成参数、ASR、实际时长和 item playbackRate。按相同字数口径比较语速，同时听最终混音。英文名称、数字的字符统计不等于中文音节，统计只能定位候选。

样片第二版把第五段从 0.8 改为 1.0，并改写表达指令，虽将源音频从 17.808 秒缩至 14.040 秒，用户仍明确反馈音色与相邻段不同。因此这不是已完成的声音修复，不能把“时长变短”记成“声音通过”。

优先继承相邻已接受段落的完整生成参数：具体音色、引擎/模型、语速、音高、情绪、稳定度、语言和表达指令（仅采用工具实际支持项）。先缩短文案，再生成问题语意段；不要只保留相同 voiceId，却同时改变语速和表演方向。第三版缩短第五段并恢复原参数，源配音 12.816 秒，压缩真实停顿后约 11.8 秒，播放速率保持 1。这个方法已验证参数一致、文本和时序正确；音色听感仍须真实听审，不能由参数一致推导为已通过。

等待 ASR ready，更新实际 asset 和时长，再重排受影响旁白、画面、MG、字幕；保留原源音频供回退。生成存在表现差异，即使参数相同也不能保证每段音色完全一致。出现持续差异时先提供实际对比和待解决项，不盲目付费抽卡。

## 字幕末尾过久

先读 Card 和词级时间。若工具已有整体 Card 起止控制，直接按接口修正再验证。没有时不要捏造参数；本案例证实仅拆分连续音频片段不会减少字幕末尾停留。只改 token 结束时间也不等于改 Card 边界。

对确实需要紧凑节奏的生成解说，可以使用 ChatCut `clean_script` 的 `only:"silence"` 压缩真实停顿，本案例使用 `silence:"compress:180"`。调用前读取 Script/工具说明、备份时间线并预留 intent；该调用立即改动时间线，没有预览。不要删除字词，不要套用于有表达意义的采访停顿。结果要检查，不能承诺同一参数对所有素材有效。

清理后刷新字幕，并读取新的 timeline 和完整源 ASR。案例中 33 处停顿缩短约 5.2 秒；36 条字幕相对帧内词时间的末尾停留均不超过 200ms。按未量化源 ASR 投影核对，最大 203ms，保留这项真实结果（30fps 半帧量化容差内）。原片是 19 条超 200ms、最长 423ms。

一个需要防范的实际边界错误：源窗口尾部向上取整后，与下一片段重叠 6.667ms，导致“按官方介绍”后多出“训”。检查每个片段的 sourceRange，不只看 timeline 是否相接。将上一片尾缩短一帧，在无词的停顿内留下 1 帧间隔，刷新字幕，确认不再重复或截断字词。不要只删显示文字掩盖音频重叠。

完成时序修复后，对旁白轨添加工具支持的极短音频过渡。本案例 `smooth_audio` 使用 2 帧交叉淡化与 2 帧端点淡化；不得让淡化吞掉辅音、叠出重复字。该工具不会替代听审。

## 画面瞬切

用 FFmpeg 只读扫描源视频剪辑点（例如 `select='gt(scene,0.22)',showinfo`），再看每个镜头中段和切点两侧像素。把源剪辑点映射到实际保留区间，计算首个残片、内部每个镜头和最后残片的实际时间；默认不足 0.8 秒为待检查候选，不自动删除。

样片原视频在 12–18 秒、98.5–101 秒包含短蒙太奇，其他区间的边缘还残留人物画面。选择同事件中完整对接、触碰、移动和拿杯动作，入出点落在正确镜头边界。改后不能只核对“无短片段”：还要确认动作与旁白语义一致，不能为了延长时长重复动作或拉慢动作。

## 整句对应画面

字幕跟上声音，不等于镜头跟上语义。将“正在对接零件”“有没有接牢”“把杯子拿起来”等具体动作句的首词到末词设为保护区间，按最终 ASR 投影计算。镜头可以在同一动作的连贯角度间切换；切到解释图或下个话题应在末词后留出约 100–300ms 的理解时间，必要时更长。

样片第二版对接画面在 8.1 秒结束，而“接牢”到 8.807 秒才结束。第三版将完整对接片段保留到 9.533 秒，并查看末词、切前和切后的合成帧。不能用延长某一无关画面来让时间检查通过。分镜记录确实看过的动作、对应 item IDs 和整句边界；`review_sync.py` 的 semantic_anchors 仅检查这些声明的时间覆盖，语义相关性仍靠像素判断。

## 用 B-Roll 替代长卡片

先查看真实参考的时间序列，记录动作钩子、展示/操作界面/特写的交替和完整动作保留方式；不要仅看封面便声称学习了节奏。本次参考 [MKBHD 的机器人短片](https://www.youtube.com/watch?v=v-_d2e7x4KA) 前 36 秒：动作先行、界面跟随讲述、必要动作持续展示。借鉴一般剪辑手法，不照搬品牌或原片文案。

为每段收集能解释该句的实拍细节。样片新增训练中心、真实操作、仿真、人类示范，删去长时间静止的解释卡，使用短标注、轻推近和少量关键词强调。旧画面持续标明资料日期；回放只在解释记忆等有实际编辑目的时使用，并明确标为“回看”。横屏可采用同步暗底与独立前景，关键工具、杯子或双手不完整时改用宽画幅，不能为填满竖屏牺牲证据。

## 可重复诊断

`scripts/review_sync.py` 只读检查导出 SRT、最终 ChatCut 时间线和源词时间，并检测短镜头残片。它不会剪辑、生成字幕或宣称完成听审。默认针对本插件的 A1 旁白、30fps；输入形状不一致时先核实工具 schema，不猜单位。

证据 JSON：

```json
{
  "timeline": {"timeline": {"entries": []}},
  "captions_text": "read_captions 返回的完整 Card 文本",
  "voice_sources": [{"assetId": "完整 ID", "data": [{"transcript": {"status": "available", "ranges": [{"segments": [], "truncated": false}], "truncated": false}}]}]
}
```

`entries` 保存 `preview_timeline` 的完整、已分页合并的条目：item.kind、itemType、trackAlias、id、asset.id、sourceRange（微秒）、timelineRange（帧）。segments 保存 `inspect_asset` 完整 transcript 的 startMs/endMs/text；截断不可用。cuts JSON 为 `{ "视频完整 assetId": [原片切点秒数] }`；先从下载片段本地坐标换算到该 ChatCut asset 坐标。

```sh
"$PYTHON" "$PLUGIN/scripts/review_sync.py" --evidence "$RUN/final-evidence.json" --srt "$RUN/final.srt" --cuts "$RUN/cuts-by-asset.json" --output "$RUN/sync-report.json"
```

报告保留文本差异、起点偏差、末尾保留、严格 200ms 超标及半帧容差结果、部分字与重复源字、全部保留镜头和短镜头候选、每段语速。文字未完全对上时拒绝输出伪精确时差。返回 2 表示存在需检查的候选；这些诊断不等于主观质量结论。

最后检查实际导出 MP4：全文件解码、全音轨响度/峰值、切点前后和关键语义时刻的合成像素。保留每项 evidence。没有真实听觉检查能力时必须写 `audio_listening:unverified`，不能把转录、波形或播放器点了播放当成听过。

可选 `semantic_anchors` 示例（放入证据 JSON 顶层）：

```json
{"semantic_anchors":[{"phrase":"还得知道有没有接牢","visual_item_ids":["完整 item ID"],"hold_ms":100,"visual_basis":"看过的对接动作及对应合成帧"}]}
```

同一句出现多次时加 1 起算的 `occurrence`。多个连贯角度可共同覆盖；中间有空隙、提前离场或短于要求的尾部停留会列为问题。缺少锚点标为未验证，不从字幕自动猜画面含义。`voice_sources[].data` 保留 `inspect_asset` 的 `asset.generationRecord.params` 后，可比较已记录的声音控制；未知记录不能算一致，匹配也不代表听感通过。


## 整片提速、动态文字与纯器乐（第四版）

整片提速时，统一改六段的生成语速，继承相同音色、语言与表达方向；不要只加速某一段，也不要假定时间线 playbackRate 会保留音高。第四版同音色速度参数从0.8统一至0.9，源旁白合计71.448秒；压缩真实停顿后旁白约67.07秒、画面67.47秒，原片动作与音频播放速率仍为1。所有原片首尾要重新过剪辑点诊断，不能只按比例缩短镜头。保持旧版独立时间线，修改动画时新建资产，避免共享资产把备份也改掉。

动态文字用于短时强调：逐字弹入、重点字轻放大、强调条擦入和退出；记忆回看使用独立的步骤条。先看同风格真实参考和目标合成帧，制作一处并检查入场/稳定/退场再批量。MG以实际内层时长完成退出，不能只缩短外层item。代码直接内联ChatCut，禁止用本地JSX文件绕过其渲染契约。

章节切换可实时浏览原生转场库，本例使用whip-pan、anticipation-zoom和clean-line-wipe，每处12帧。不要固定为所有项目通用预设；先满足动作句保护，再检查转场开始、中间和结束。第四版给同步暗底与前景同时加转场时，中间帧的暗底变亮，移除暗底转场、保留前景转场后恢复可读性。故透明度和画幅不同的双层素材要检查组合效果，不能仅凭结构里有transition就通过。

第四版配乐按用户已选纯器乐生成，人声放anchor轨，配乐独立follower轨并按响度初始化压低；这只是当时的设置，后续第五版在短停顿发现释放回弹，不能当作已验证安全的通用预设。不要给 follower 再叠加大幅负增益；采用稳定电平修复时同步取消 follower，详见 [停顿处配乐检查](music-pauses.md)。配乐裁到真实画面尾部（计算时排除BGM自身），保留秒单位的淡入/淡出；长配乐不能延长成片。核对实际导出峰值、响度及全部人声间隙，再听混音；没有音频理解能力时不能据此宣称音乐好听或不抢人声。

本例ASR修正后，一个源的inspect_asset仍返回旧缓存；read_script(refreshCache:true)刷新后再读取源词时间，与Card和SRT对齐。只在源文字已证实修正且读取不一致时刷新，不修改证据文本来伪造一致。原片镜头时长恰好0.8秒时，用微秒级数值容差避免0.799999999999997的浮点误报；仍会标记真正少一帧的短片段。


转场还会读取可见剪辑区间外的源画面。第四版首次云端导出在20秒附近带出一个人物闪帧：入场素材恰好从原片切点开始，变焦转场取用了切点前的余量。对12帧居中转场，检查入场前6帧与出场后6帧均在同一个正确源镜头内；预留这段余量时也检查调整后的另一端，避免新造短残片。重新预览和检查导出中全部转场帧。review_sync.py 的 transition_handle_candidates 会列出余量跨越源切点的候选，不能只检查可见sourceRange。跨角度如果确有编辑目的可经像素判断保留，不能把数值诊断当作自动审美决策。

SRT与画面Card可能存在一帧量化差异。本例六个相邻字幕边界相差约33ms，完整文字一致，所有源语音偏差在约200ms及半帧量化容差内。应明确记录差异，不写“完全相同”，也不修改词时间来伪造一致。
