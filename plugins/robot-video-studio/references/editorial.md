# 采编与画面选择

## 搜索与选题

按用户时区确定今天，搜索最近 72 小时；不足时扩大到 7 天。优先追溯机器人公司、实验室、论文作者、活动现场发布者，其他媒体补充对比与背景。X/YouTube 的搜索与网页读取由宿主联网能力执行，下载器不承担全网搜索。用真实搜索结果中的 URL，不编造帖子、视频 ID 或播放量。

先读正文/原始公告，再判断时效：记录 event_date、published_at、retrieved_at。转载新日期不是新事件；预告中的未来演示不能写成已经实现。没有可靠热度指标时称“近期候选题”，不称“全网最热”。单题候选应有核心问题、一个具体看点、至少一处真实视频证据，以及可讲清的限制。合集每条新闻有独立事实来源，最多三条。

向用户展示 2–3 条候选，包含标题方向、为什么值得看、事件日期、1–2 个出处、可用画面、预计时长与推荐理由。选择已给定后不重复询问。用户未选前可继续配置、核实来源和只读探测，不开始付费生成或批量下载。

## 来源与片段

- source 的 `kind` 为 video/article/paper/image；同一视频的多个片段用同一 source id，下载记录区分时间段。
- 默认 2–5 个视频源，最多 6 个；片段合计 300 秒内。长源只获取明确有用的片段，保留前后少量上下文。只有整段确实有用且本身很短才整段获取。
- `rights` 使用 available_license、permission_confirmed 或 unknown，并记录可见的具体条款/授权依据。来源水印、作者、原始链接保留。非商用不是许可状态。
- 原始 URL 与元数据证据不能被带签名的临时下载 URL 替代。用 yt-dlp 返回的发布时间核对网页；证据冲突则待核实，不猜。
- 无法下载：先重试同一个片段，随后找同一事件的官方镜像或另一可靠现场来源；仍失败则向用户说明具体缺口。不要下载整个播放列表，也不要自动读取浏览器 cookies、安装绕过插件或索要账户密码。
- 区分遥操作、预编程、仿真与自主行为。演示里没有证据支持的泛化能力，不写成现实部署结果。人物/单位宣称按归属描述。历史对比镜头在画面标注年份。

## 自然口吻

开头用具体动作或矛盾：能完成什么、卡在哪里、为什么这个改进值得看。每句话承担一件事，多用动作和具体名词。少用“颠覆”“震撼全球”“未来已来”。不每段都说“首先/其次/最后”，不虚构亲测经历或情绪反应。

60–120 秒通常从约 250–450 个汉字起草，以真实配音时长为准；不要为凑字数牺牲事实。对复杂机制，只解释理解这个热点所需的一层。最后给明确结论或仍待验证的问题，不机械添加关注引导。

## 画面与节奏

观看一段动作的起点、过程与结果，不能只靠代表帧认定成功。旁白提到某个零件、动作或限制时，画面必须指向它，必要时用指示或简洁示意。单纯装饰动画不能替代不存在的证据。

不强迫所有镜头全屏裁切；手、工具、接触点、移动路径优先保留。可将横屏演示置于竖屏中部，上下留给标题、出处或图解，避免相同画面模糊填充占据主要视觉注意。留出动作的完整节奏，有明确意义时才换镜。
