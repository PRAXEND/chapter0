# Robot Video Studio

## 工作约定

目标是有真实画面和事实支撑、能看完的 60–120 秒机器人视频。默认 9:16、1080×1920、30fps、90 秒中文解读。支持单热点解释或最多三条新闻的合集。用户本次明确要求优先于已保存默认值。

插件根目录是本技能目录上两级。先读配置 `python <plugin-root>/scripts/studio.py profile` 和已有 run；没有配置时用 `setup-robot-video`。工具参数以当前 ChatCut MCP schema 为准；按需读取已安装的 ChatCut 技能，绝不硬编码其缓存版本路径。声明依赖并不保证工具或技能可用，先检查。

通常只停在选题选择及首次具体音色选择；用户选题后即授权完成稿件、素材、配音、剪辑、字幕、检查与导出，不再逐步索取批准。遇到真实的访问、宿主审批、额度或关键素材缺口再说明问题。明确指定题目可视为已选择，不机械再出候选题。不得自行发布或建立自动任务。

## 开始或继续

- 新一期用 `studio.py new --title <标题> [--output-root <目录>]` 创建运行目录。记录在 `run.json`；用 `studio.py status --run <目录>` 读进度。每期独立 ChatCut 项目，除非用户指定现有项目。
- 运行目录保存来源、分镜、验收证据和交付文件；个人音色与凭据不进入分发包。具体命令和状态写入规范见 [运行记录](../../references/operations.md)。
- 制作前加载 ChatCut `chatcut-plugin-basics`，新建项目后立即展示真实 editor 链接并按工具要求完成 browser handoff。不要覆盖用户已有项目或猜 ID。
- 恢复时先读本地记录，再读 ChatCut 最新项目/任务/资产状态。记录为 `reserved` 的外部操作结果未知，必须先核对服务端；不能当失败重新提交。生成、导入与导出都记录 intent key、输入摘要、任务和对象 ID。

## 选题与素材

读取 [采编规范](../../references/editorial.md)，用当前联网搜索获得 2–3 个可拍的候选题；默认近 72 小时，必要时扩展至 7 天并披露。候选题需有切入点、事件日期、主要出处和实际可用画面，而非只有文章标题。没有可信近期题目时明确说明，可提旧题解读但不得伪装热点。

用户选择后，把来源和分镜写入运行记录，再获取媒体。`studio.py probe --url <url>` 只读元数据，`fetch --run ... --source ... --start ... --end ...` 获取选定片段。最多 6 个视频源，下载片段合计不超过 300 秒，默认 2–5 个来源。不下载播放列表、直播或长节目全片。下载失败找同事件替代来源，不绕过付费墙、DRM 或宿主拒绝；不得擅自提取浏览器 cookies。

任何内容相关的公开可访问来源都可作为候选，事实证据仍尽量追溯原始来源。保存作者、原始链接、事件/上传时间、截取区间、许可信息及未知项。公开和非商用不等同于已授权；不伪造许可，不移除来源水印，不将权利不明标成已完成授权核验。

## 脚本、声音与画面

新片和重剪都先读 [开场、布局与节奏复核](../../references/editing-rhythm.md)。前几秒兑现具体看点；逐镜决定主体放大或完整动作布局；检查旁白内部长停顿、空图解和重复原片。目标时长不是必须填满的长度。沿用已接受的克隆录音和配乐时，先做语义重排及稳定混音，避免无必要的重新生成。

1. 先查看原片代表帧、完整动作区间和必要转录，建立逐段分镜：旁白、事实依据、画面锚点、原片区间、目标时长。每句具体论断必须找到对应证据。检查原片内部剪辑点和所选区间的首尾残留，默认将不足 0.8 秒的镜头列为候选问题再目视判断；时间线上一个素材也可能包含连续瞬切，不能只看剪辑片段长度。
2. 写成能自然说出口的中文。按“具体看点—演示与解释—局限或意义”推进，不机械套标题、三点论或关注口号。专名与数字建立发音/字幕对照，不用错字字幕掩盖配音读错。
3. 读取 ChatCut `voice`。首次按配置技能试听确认，后续实时解析已选音色。按语意段生成旁白，使用该音色实际支持的控制项，不臆造精确时长控制。完整新片采用旁白驱动剪辑，但真实动作必须有足够展示时间；已有固定画面配音或改稿则同时读 `voice/references/video-sync.md`，尊重原来的同步约定。
4. 生成完成且转录 readyForEditing 后，再读取一次真实音频时长与转录时间戳，更新分镜的音频 asset、timeline frame 与视觉对应关系，再批量放置。刚生成但转录仍 idle 的 durationMs 可能还是估计值，不能用于最终排镜。逐段比较真实语速和生成指示；时间线 playbackRate=1 不代表生成时没有变慢。只修正有问题的语意段；每段最多一次自动重生成，更多付费尝试先说明。内容不匹配不能通过全局加速、重复镜头或硬拉音频解决。
5. 通过 ChatCut `asset-import` 导入独立素材并制作时间线。下载片段仍是独立来源素材，保留原片偏移；最终取舍、排列、裁切、字幕、混音与动画均在 ChatCut 内完成。FFmpeg 仅用于素材获取所需解封装/片段下载、检查和抽帧，不本地合成主成片。
6. 默认分层：底层演示画面、解释性动画、字幕；独立旁白、现场声及可选轻音效。横屏原片优先完整呈现机器人和操作对象，可用竖屏上下排版；不能为了铺满画幅裁掉关键动作。必要现场声压低混入，避免与解说争抢。未请求配乐时不自动生成音乐；已要求配乐时读取 ChatCut music 与 talking-head-guide 的 audio-and-music 参考，沿用已确认的有唱/纯器乐选择。

局部重配音先对照相邻已接受段落的完整生成参数，优先改短文案；相同音色 ID 不代表改变语速和表达指令后仍有相同听感。对每个关键动作句记录首词、末词及相关画面 item IDs，画面至少覆盖整句并留出理解时间，再检查切点两侧。详见 [整句同步与声音修复](../../references/repairs.md)。

有 BGM 的新片或修订必须读取 [停顿处配乐检查](../../references/music-pauses.md)，记录真实 music_tracks；修改旁白停顿后也须重新检查配乐自动压低的释放。仅音量问题不需重新生成音乐。

当用户反馈“像 PPT”“枯燥”或要求参考创作者时，查看真实科技短视频的一段时间序列，提取可复用的动作开场、操作特写和演示节奏。用相关实拍 B-Roll 替换长卡片，MG 改为短时强调；旧资料和有意回看在画面中标注。不能把所有镜头强制裁成同一竖屏尺寸，也不能按固定秒数打断动作。

用户要求整片更快时，可以沿用同一音色和表达方向，统一调整所有段落的生成语速，再根据实际 ASR 重排；这与只修一段的参数继承不同。节奏、动效和配乐的具体做法见 [已验证的修复方法](../../references/repairs.md)。

## MG 动画与字幕

- 读取 ChatCut `create-motion-graphics`，浏览真实参考并检查目标帧。可沿已确认的克制科技风格自主选择参考，先做一处合成验证再批量。所有内容、字体、颜色等通过编辑属性暴露。MG JSX 直接内联交给 ChatCut，不写成本地生成视频或文件再导入。
- 动画用于解释关键数字、原理或结构，不每句都放卡片，不用转场掩盖逻辑跳跃。动作保持完整，切换跟随语义和视线；无需每 2 秒强制切镜。
- 读取 ChatCut `transcription`，确认最终旁白转录完成，启用只以最终旁白为来源的字幕。校正专名、数字、标点与换行，避免原片旁白也重复生成字幕。两行以内、适当留白，不遮操作对象和平台底部 UI。源 ASR 的同音字和专名错误应通过 `manage_transcript fix` 预览后修正；仅修改显示 Card 可能不会进入独立 SRT 导出。导出后实际读取 SRT，逐项核对修正是否保留，不能只验证画面字幕。
- 上游时序变化后重新检查配音、字幕、动画和现场声；不要保留旧时间戳。需要编辑已有录音的语义内容时才加载 `talking-head-guide` 与 Script 流程，不把新生成解说机械套成去口癖任务。
- 若字幕末尾停留、局部语速异常或画面瞬切，读取 [已验证的修复方法](../../references/repairs.md)。字幕边界不能直接编辑时，可在适合收紧节奏的旁白中压缩真实停顿后重建字幕；不能靠改词时间伪造边界。停顿清理后检查相邻源窗口是否重叠到同一个字，重排全部受影响画面和动画，并检查成片。

## 验收与交付

`audit --evidence` 同时生成 `editorial-check.json`，扫描长停顿、长镜头和重复源区间。检查候选像素后才能按具体理由保留完整动作；另记录开头和布局证据，以及 `editorial_rhythm` 审阅。不得用模板文案代填。实际导出必须检查；若 SRT 与烧录字幕分帧不同，按节奏复核文档保留原件、验证真实切换帧，再决定是否确定性重建交付字幕。

读取 [验收标准](../../references/quality.md)，完成结构检查、合成画面检查和声音检查。任何缺少证据的检查标为未验证，不填写假通过。用 `studio.py audit` 做文件和分镜的客观检查；有配乐时提供当前完整时间线、源 ASR 和配乐轨道证据，自动扫描最终 MP4 的旁白停顿并保存 music-pause-check.json。有候选或缺少证据时保留 music_pause_levels 待复核；听审短停顿和片头片尾，不能把自动扫描当作整片听过。确认不需要的自动压低回弹后，按参考文档局部修复、重新导出并复测。

加载 ChatCut `verification` 与 `export`。最终交付已在本工作流授权：用 `submit_export` 导出 H.264 MP4（默认浏览器本地渲染）、SRT，保存 renderId，使用 `track_export` 等到完成。任何云端回退应确认素材 readiness 和是否增加费用，不把本地导出失败偷偷转换为付费路径。不能用仅排队的任务或无法访问的 URL 宣称交付成功。

交付 MP4、SRT、可编辑项目链接、脚本、来源清单和验收报告。可同时提供短标题建议。只有技术检查和有证据的声画审核都完成才将运行标为 completed；否则标记具体 pending 项并提供已完成结果。
